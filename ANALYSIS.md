# Source analysis

These sources were read as shallow clones on 2026-10-21. Only review-relevant files
were read, and nothing in them was run.

| Source | Does well | Lacks | We adopt |
|--------|-----------|-------|----------|

The C# file covers the right traps (`.Result`/`async void`, captive scoped services, N+1, cartesian explosion, HttpClient, HttpContext off-thread). ## Gaps no source covered, written fresh

- **Cross-stack contract** (C# DTO ↔ TS types): nullability on the wire, int-vs-string enums and reordering, `DateTime` kind and `DateOnly` parsing, `decimal`/`long` precision past 2^53, ProblemDetails parsing, and stale NSwag/orval clients.
- **Migration safety**: rename-as-drop+add, non-nullable columns without a default, type narrowing, locking during index builds, and expand → migrate → contract deploy order.
- **Vertical + horizontal passes** as a required structure. Bugs between layers sit at the hops, and drift shows up among siblings.
- **Diff-driven loading**: references are picked from changed paths, not from the repo's languages.

## Key adoption decisions

1. **The verification gate requires a concrete breaking input** (from Anthropic's validate-then-filter step and dotnet/skills' evidence gate). It replaces confidence scores and keeps the report short without dropping input-dependent bugs.
2. **References load from the diff's paths, not the repo's languages** (a fix for code-review-skill's load-by-language). Each reference opens with a checklist, and snippets are read only for checklist items that hit.
3. **The cross-stack contract is its own reference.** None of the sources treats the C# ↔ TS boundary, the place where a .NET + React codebase breaks most often between deploys.
